# 共度 · 一起听服务

This private-instance adapter provides the music library and login endpoints for the Android 共度「一起听」room. It reuses the pinned one-earbud NetEase client and credential store. Android maintains the playback queue and playback state in one place, so the human controls and assistant tools act on the same player.

## Run locally

Requires Node 20 or newer. There are no npm dependencies.

1. Copy `.env.example` to `.env`.
2. Generate a token with the command in that file and set `LISTEN_TOKEN` to the result. The token must have at least 24 characters.
3. Run `node --env-file=.env server.js` from this directory.
4. Configure the server URL and token in the App's「一起听」settings. The URL is the server origin, such as `https://listen.example.com`.
5. Generate the login QR in the App and confirm it with your NetEase Cloud Music account.

For a remote phone, place the service behind the instance's HTTPS reverse proxy and route the `/api/listen/` prefix to port 8787. The default process binds to `127.0.0.1`. This service uses a single music account for the private instance.

## Docker

After setting `LISTEN_TOKEN` in `.env`, run `docker compose up -d --build`. Compose publishes only `127.0.0.1:8787`; the reverse proxy supplies HTTPS. The named volume `listen-data` preserves login state and song notes.

## API

Every request uses `Authorization: Bearer <LISTEN_TOKEN>`. Tokens in query strings are not accepted. Responses use JSON, `Cache-Control: no-store`, and `ok: true` on success. Failures use a non-2xx HTTP status and `{ "ok": false, "error": "CODE", "message": "可显示的说明" }`.

| Method | Path under `/api/listen` | Success fields |
|---|---|---|
| GET | `/health` | `service`, `version` |
| GET | `/login/start` | `key`, `qrUrl`, `expiresAt` |
| GET | `/login/status?key=…` | `status` of `waiting`, `scanned`, `authorized`, or `expired` |
| GET | `/login/account` | `loggedIn`, `nickname`, `avatarUrl`, `vip` |
| POST | `/login/logout` | same account fields, with `loggedIn: false` |
| GET | `/search?q=…` | `songs` |
| GET | `/song?id=…` | `song` |
| GET | `/url?id=…` | `url`, `trial` |
| GET | `/lyrics?id=…` | `lines`, `pure` |
| GET | `/daily` or `/radar` | `songs` |
| GET | `/playlists` | `playlists` |
| GET | `/playlist?id=…` | `songs`, capped at 500 |
| GET | `/notes?id=…` | `notes`, `feeling`, `favoriteLines`, `tags` |
| POST | `/notes?id=…` | same fields; a JSON object updates the supplied fields |

A song has `{ id, title, artist, album, cover, durationMs }`. A playlist has `{ id, title, cover, count }`. A lyric line has `{ timeMs, text, translation }`. IDs are numeric strings. The login `qrUrl` is the NetEase scan target URL; the App generates its QR bitmap locally. The response also includes an optional locally generated SVG data URI as `qrImage`. QR status accepts only keys generated by this instance, and the pending keys expire after the supplied deadline.

Playback URLs are requested when needed and can expire. `trial: true` represents a trial stream returned by the music provider. The App handles playback and retries using its native player.

Each upstream request has an eight-second total deadline, including slow response bodies. Endpoints that need two upstream calls stay within the App's eighteen-second service timeout. Provider business errors, incomplete responses, and timeouts are reported explicitly instead of appearing as empty recommendations or playlists.

## Storage

`LISTEN_DATA_DIR` defaults to `./data` in local configuration and `/data` in the container. The `netease-auth.json` file contains the private login cookie and uses mode 0600 on POSIX. It is excluded from Git and Docker build inputs. Public account responses expose nickname, avatar, and membership status. No API returns the login cookie.

Song notes use atomic per-song JSON files under `notes/`. A write that supplies only `feeling` preserves the existing notes, favorite lines, and tags. Notes accept up to 4000 characters, feelings up to 1000, favorite lines up to 20 entries of 300 characters, and tags up to 20 entries of 40 characters. Invalid or oversized fields reject the update and preserve the saved data. Corrupt saved notes produce an error and retain the original file for recovery. A single process owns the data directory.

## Verify

Run `npm test`. The tests exercise real local HTTP requests with a stub music provider, plus the source client's real response parser with a fake HTTPS transport. They cover token authentication, QR login/logout concurrency and expiry, cookie privacy, source models, note persistence, provider failures, interrupted responses, response limits, and total timeouts. A real NetEase login, account availability, music playback, and reverse proxy connection still require instance and phone acceptance.
