# 聊天图片列表、预览与插件选图

需要插件启用且声明 `conversation_sync` 权限。插件参数使用 `chat_images_list`、
`chat_image_base64` 或 `chat_image_mime` 时，模型可以使用宿主工具 `chat_images`。

- `{"action":"list"}`：返回当前调用分支最近 30 张图片的 `attachment_id`、`message_id`、名称、
  `origin`（`user` / `assistant` / `tool`）、工具名称和原始尺寸。某张图片读不到会在该项标明，其他项继续返回。
- `{"action":"preview","attachment_id":"attachment_…"}`：返回指定图片的单张预览附件、原始尺寸及
  `original_sha256`。完整等比缩小，最长边 640 像素。预览放在应用缓存目录，系统清理缓存后可能需要重新查看；
  预览输出不会成为图库列表中的新候选，也不会自动上传图库。
- 调用插件上传时，把预览的同一 `attachment_id` 传给插件工具。即使旧插件没有在 manifest 声明该参数，
  宿主也会向模型暴露它。Base64/MIME 字段继续由宿主填充，模型不能伪造。

多图时省略、传 null 或空编号会失败，禁止默认改用最新图。单图时保留省略编号的兼容行为。
错误编号、其他聊天/分支编号或已经编辑掉的附件不会退回其他图。

插件工具的结果后会附 `chat_image_input` 回执，记录实际选中的编号、来源、原图哈希、
送入插件的图片哈希和尺寸。原图超过原有大小阈值时会缩小到最长边 1600 像素，两个哈希可能不同。
回执仅证明宿主向插件传入了哪张图，插件服务器实际保存的内容仍需核对服务器结果。

模型的工具集合使用调用开始时的分支快照，同一轮里新生成的图片需下一次消息才进入列表。
非用户来源依旧仅接受应用 `files/images`、`files/upload` 内的真实图片附件；文字路径、远程 URL、
其他应用 content URI 和越界路径不会作为工具图片读取。

这次修改覆盖宿主列图、预览与注入链路。图库插件页面自身的方形封面样式不在本次修改范围。
本地定向回归与真实手机、图库服务器上传验收分别记录，不把合成测试作为真机结论。
