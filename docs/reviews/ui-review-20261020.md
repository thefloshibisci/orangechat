## 审查发现与修复状态

### P1：Web 鉴权运行时切换（已修复，单元测试通过）

`WebApiModule` 现在始终安装鉴权插件，由 `WebAccessAuth` 在每个请求上读取当前启用状态和密码。关闭鉴权启动后再打开会留下公开路由的问题已移除；密码为空时受保护路由保持关闭。真实网络客户端上的并发设置切换尚未做设备验收。

### P1：整包备份恢复（已增加暂存、日志与启动恢复，测试通过；不保证并发可见原子性）

S3、WebDAV 远端和本地 ZIP 均走共享暂存和恢复事务。恢复先解包/校验，写入持久化日志并保留原文件；数据库在启动阶段激活前保留事务记录。失败或进程中断时，启动恢复可完成回滚或提交。五项事务测试覆盖替换、崩溃标记和恢复流程。

方案提供崩溃恢复，不会让多个文件与数据库在运行期间同时原子切换；本轮没有在真机上执行破坏性磁盘故障注入。若回滚文件本身不可读或存储损坏，应用会阻止以混合数据继续启动，需人工恢复。

### P2：Web 服务生命周期并发（已修复，单元测试通过）

启动、停止和重启现在由互斥生命周期状态串行处理，并在取消时完成关键关闭/创建过程。四项确定性测试覆盖重复启动、停止和重启顺序。设备端监听端口及进程被系统强制终止的行为未做运行时验证。

### P2：插件 WebView JavaScript 桥接（出口统一编码；hook 名边界已修复，定向测试通过）

插件桥接回调统一将 callback ID 和结果编码为 JSON 数据。本轮发现 hook 配置的函数名仍能进入脚本语法，现限制为 JavaScript 标识符、以 `window[...]` 取函数，并把上下文及返回 JSON 字段安全编码。测试覆盖恶意函数名、引号/换行及 JSON 类型。

插件本身仍是可执行代码且具有其获准权限；此修复仅防止 hook 配置/桥接数据意外成为脚本。尚未做完整威胁建模或动态插件渗透测试。

### 聊天专项备份范围与恢复语义

入口为“备份 → 本地 → 仅聊天记录”。独立 ZIP 格式包含所有会话、完整备选消息分支、压缩状态/历史、节点收藏和被引用的本地附件；语音及工具输出内的附件均显式遍历，远程链接原样保留。不会导入模型提供商、插件或助手配置。缺失助手映射到导入时选定的本机助手（失效时选本机有效助手）；无效文件夹归属清空，不导入其他安装的工作区路径。

用户最新要求按完整会话处理：**增量恢复只新增本机没有的会话 ID，同 ID 会话原样保留本机记录；覆盖恢复新增本机没有的会话，并完整替换同 ID 会话。两种模式均保留备份之外的本机会话。** 已移除消息/节点/分支合并算法。增量遇到同 ID 会话在写入数据库前直接跳过，不修改其元数据、消息、所选分支、压缩状态、收藏和搜索索引，也不发布仅被这些跳过会话引用的附件。恢复结果显示实际新增及跳过数量。

### 一致性与边界

- 导出在 Room 事务内读取一致逻辑快照，不通过复制整库夹带其他数据，不在导出时执行附件修复。快照后附件若已不可读，导出明确失败。
- 导入先解包并校验：固定清单格式/版本、路径白名单、重复条目/ID、分支选择和摘要覆盖；附件清单必须完整。限制实际解包字节（总计 2 GiB、JSON 128 MiB、最多 100000 条目），不信任 ZIP 标称尺寸。空附件、未归档本地 URL 和缺失附件拒绝导入。
- 待恢复任务在私有 no-backup 目录持久暂存，校验并同步文件后才原子发布待恢复指针；可在界面取消。下一次启动，在 WorkManager 初始化和 ChatService 预热前执行，避免旧会话缓存和晚到写入覆盖结果。
- 会话、节点、节点收藏与严格 FTS 重建在同一 Room 事务内更新；任一失败整批回滚。全局节点 ID 冲突明确拒绝，不能借 REPLACE 抢占别的会话。普通对话保存继续使用原有精确增量路径。
